    DNS-over-QUIC (RFC 9250) with Fail-Closed Safety

    Allowed DNS queries are multiplexed over QUIC streams on UDP port 853, avoiding TCP head-of-line blocking during Wi-Fi to mobile handoffs. If an encrypted upstream cannot be reached, AdShield returns DNS SERVFAIL rather than silently downgrading to plaintext UDP 53.

          Does DNS filtering stop every ad or tracker?+

          No. AdShield Pro blocks lookups to domains that appear on your enabled lists. Ads served from the same hostname as the page or app itself, and anything inside an already-encrypted connection, cannot be separated by DNS alone.

          Is AdShield Pro a full VPN or a security suite?+

          No. AdShield Pro is not a full VPN: it uses Android’s local VpnService TUN interface to intercept DNS packets only, with no remote exit node and no traffic relaying. It is not an antivirus either, and it does not inspect encrypted page content.

          Which encrypted transports are supported?+

          DNS-over-HTTPS (RFC 8484), DNS-over-TLS (RFC 7858), and DNS-over-QUIC (RFC 9250). If every encrypted upstream fails, queries return SERVFAIL instead of silently falling back to plaintext port 53.

          Where does my DNS history go?+

          Query matching and the activity log are processed on-device. The activity log can be cleared at any time, and the app ships no third-party analytics SDK. See the privacy policy for the full data map.

          How do I report a bug or request a capability?+

          Use the #support or #filter-lab channel on the Discord server, or open an issue on GitHub. Requests are tracked against the public capability matrix.
