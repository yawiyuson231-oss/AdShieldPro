# Audit & fix pass — 2026-11

Scope: the whole repository — browser platform (`app.js`, `engine.js`, `sw.js`, `dns/`,
`aether/`, `security/`, `guard/`, `ui/`), Cloudflare Worker API (`cloud/`), Chrome
extension (`extension/`), Android/Kotlin sources and the Python governance tooling.

Method: baseline the gates first (they were green), then audit the *paths* rather than
the text — what the UI reads versus what the modules produce, what the documented
contract says versus what the code does, and what a latent failure (power loss,
provider outage, hours of idle time, a mistyped pattern) would look like.

Every item below was a real defect in shipped code and now has a regression test. No
feature was added; nothing in the protection path was weakened.

## Browser platform

1. **Dual-stack DNS results were blank in the UI.** `DnsClient.lookupDualStack()` returned
   `ipv4`/`ipv6` but not `results`, `ttl` or `latencyMs`, while `renderDnsResult()` rendered
   `result.results.a/aaaa` — so a "dual" query threw `Cannot read properties of undefined
   (reading 'a')`, and the fields it did have printed `TTL —`. The report now carries both
   per-family results plus top-level `status`/`ttl`/`latencyMs`/`cached`/`reasons`.
   *Test:* `hardening.test.mjs` — "dual-stack results expose the fields the UI renders".

2. **A stale DNS cache entry survived a new block rule.** The stale-while-revalidate path
   called `_network()` directly, which is steps 4–6 of the pipeline and skips the filter
   ladder, so a domain blocked *after* its answer was cached kept being served (and
   re-cached) until the grace window expired. The refresh is now skipped and the entry
   dropped when the current verdict says blocked. `DnsCache.remove()` was added for this.
   *Test:* "a name blocked after its answer was cached is blocked, not served from the stale cache".

3. **Imported Android site exceptions did nothing.** `browserSiteExceptions` was stored,
   exported and displayed, but never applied to the engine — the "never filter this site"
   list was inert. `applyImportedExceptions()` now normalises and applies each entry at boot
   and after every engine rebuild; malformed entries are skipped rather than becoming a
   wildcard.

4. **Restoring a snapshot erased remembered import fields.** `applySavedState()` replaced
   `excludedAppPackages`/`browserSiteExceptions` with `[]` when the snapshot did not carry
   them (Android backups never do), silently dropping them from the next export. Fields the
   snapshot does not carry are now preserved.

5. **The custom-rule view drifted from the engine.** `toggleDomainRule()` added the new
   direction *before* removing the opposite one and pushed rules without a `matchType`, and
   the false-positive path left a stale block rule in place — so the UI could list a rule the
   engine did not honour (or vice-versa, with a duplicate allow/block pair for one host).
   Both directions are now cleared first and the pushed rule records `matchType`.

6. **The aggressive-tier off switch left its rules loaded.** Disabling rebuilt nothing and
   `enableAggressiveTier()` could return `false` while the UI toasted "enabled" anyway.
   Both directions rebuild the engine, and the toast only fires when the change succeeded.

7. **`ui/dom.js` default export was broken.** `export default { …, plural, … }` sat above
   `plural`'s declaration, so the default export carried `undefined` for it — a default
   import calling `ui.plural()` threw. The literal moved below the declarations and arrays
   are now flattened defensively.

8. **Every renderer ran on every refresh.** `renderAll()` drew all ten pages — including an
   `await fetch()` of the extension facts — on every feed save, snapshot restore and rule
   change. It now renders the visible page plus the dashboard.

9. **The header rule count went stale.** The `ready · N rules` pill and the tab title kept
   the count measured at boot after feed updates, imports and tier changes.
   `refreshRuleSummary()` re-derives it from the engine wherever the rule set changes.

10. **The dashboard over-stated the blocklist.** The KPI labelled `breakdown.total` as
    "block rules active", but that number also counts exceptions and wildcard *allow* rules.
    It now says exactly what it counts.

11. **Monitor percentiles were off by one.** `floor(p*n)` returned the 96th smallest value
    for p95 of 100 samples; replaced with nearest-rank.

12. **Idle tabs accumulated chart buckets.** Minute buckets were pruned only when a *new*
    one was created, so a tab open overnight drew a chart of empty hours. Reads prune first.

13. **Snapshot version drift.** `BackupManager` defaulted `appVersion` to `5.0.2` while the
    release is `5.0.3`, so snapshots were labelled with an older version.

## Cloud API

14. **A provider outage looked like a logout.** `requireUser()` swallowed every error,
    including a failed JWKS fetch, and returned `401`. The JWKS failure now raises
    `AuthProviderUnavailableError` and the middleware answers `503` with the reason; a
    genuinely invalid token is still `401`.
    *Test:* "an unverifiable token is answered with 503, not an opaque 500".

15. **Registration verified the same token twice.** `/v1/account/register` re-ran
    `requireUser()` after the middleware had already done it; the second JWKS lookup could
    turn a valid token into a 401 mid-request. It now reuses the middleware's claims.

16. **`version_create` was a declared audit action nothing wrote.** Replacing a file left no
    trace in `/v1/audit`. Now recorded with the new version number.

17. **Copying into a deleted folder orphaned rows.** `/v1/nodes/:id/copy` inserted a copy
    under whatever parent the original had, even after that folder was trashed, producing a
    row no listing could reach. It now answers `409`.

## Extension

18. **A write storm on every matched rule.** `background.js` awaited
    `chrome.storage.session.set` on every `onRuleMatchedDebug` event, which the API
    rate-limits — losing counts. Writes are debounced (trailing edge, 250 ms).

19. **Recycled tab ids could inherit counts.** MV3 workers restart and tab ids are reused;
    the entry of a tab closed while the worker was asleep was never dropped. A one-minute
    poll prunes ids that no longer exist (no new permission: `tabs` is not needed for
    `tabs.query`).

## Android (source-level; the Gradle build needs a JDK, which this sandbox does not have)

20. **"Protection off" could be rolled back by a reboot.** `ACTION_STOP_VPN` and `onRevoke()`
    persisted `vpnShouldRemainActive = false` with `runBlocking` on the caller's own
    coroutine context (the service scope, or the command context), and `stopSelf()` cancels
    that scope a few statements later — the DataStore writes could be dropped, and
    `BootCompletedReceiver` would then restart protection. Writes now run on a new
    `ProcessScopeOwner.appScope` (implemented by `AdShieldApplication`) and only the bounded
    wait happens on the service. The same applies to the daily-stats flush in `onDestroy()`.

## Governance tooling

21. **The boundary gate could not express a reviewed fix.** `tools/evolution/boundaries.py`
    pinned 109 protected files to one base commit, and the tampering test read the manifests
    from the module root instead of the tree under test. The gate now checks each file
    against the original baseline *and* an explicitly reviewed second baseline
    (`boundaries.audit-fixes.json`, listing the 5 files changed by this pass), requires both
    to track the same inventory, and reads manifests from the tested root. The original
    hashes are untouched and still reproduce from `4fbc131`.

## Deliberately not changed

- Only the first resolver attempt is circuit-broken (hedged/fallback attempts are not).
  Deliberate: it is what makes a fallback possible at all; the alternative fails every
  lookup while one resolver is down.
- The WebGL fallback in the Android-bundled `worldmonitor.js` clears
  `container.innerHTML = ''` before re-creating the Cesium viewer. That is removal only —
  no data is interpolated — and calling `Viewer.destroy()` on a half-constructed viewer is
  the more fragile option.
- Privacy analytics persistence is unchanged: k-anonymity, salted hashes and the 30-day
  retention window already behave as documented.
