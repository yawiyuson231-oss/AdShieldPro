Privacy & Data Safety

Privacy Policy & Google Play Data Safety Disclosure

Effective date: November 18, 2026 Application: AdShield Pro (com.adshield.pro) Companion web app: OmniShield X (/app/)

1. Core Privacy Commitment

AdShield Pro is engineered as a local, on-device privacy and DNS filtering firewall for Android, paired with a static browser-only companion platform.

  • No Root Required: AdShield Pro operates exclusively in standard Android user space.
  • No Developer Analytics or Data Sale: Neither the Android app nor the website includes developer analytics, advertising SDKs, crash-tracking SDKs, or developer-operated collection endpoints, and we do not sell personal data. External providers you deliberately use (DNS, search, cloud storage, and media) receive the requests needed to provide their service and are governed by their own privacy policies.
  • No HTTPS Interception or Root Certificates: AdShield Pro never installs a trusted root Certificate Authority (CA) and never decrypts, inspects, or modifies encrypted TLS/HTTPS application payloads.

2. How Android VpnService Is Used

AdShield Pro uses Android’s android.net.VpnService API strictly to establish a local on-device virtual DNS interface (10.215.173.1/30 and fd00:ad5:1e1d::1/126):

  1. DNS-Only Routing: Only traffic destined for the virtual DNS addresses (10.215.173.2/32 and fd00:ad5:1e1d::2/128) is routed into the local TUN interface. Non-DNS TCP, UDP, and QUIC application traffic flows directly over your physical Wi-Fi or mobile data connection without passing through a remote VPN server.
  2. Local Rule Evaluation: Each DNS query is evaluated locally in memory against your enabled blocklists, scheduled profile rules, and custom allow/block rules. Blocked domains are answered on-device with NXDOMAIN or a 0.0.0.0 / :: sinkhole. Allowed domains are forwarded using your chosen protocol: encrypted DNS-over-HTTPS (DoH, RFC 8484), DNS-over-TLS (DoT, RFC 7858), or unencrypted UDP/TCP port 53 when selected. If DoH or DoT is unavailable, the app returns DNS SERVFAIL instead of silently downgrading to plaintext.
  3. Resilience Controls (Local): Per-app DNS policies, per-network policies, scheduled Quiet Hours profiles, emergency allowlist-only mode, optional failover between resolvers you select, and DNSSEC evidence reporting are evaluated locally and stored only in on-device DataStore (and optional local backup files you export yourself).
  4. Local File Scanning: File scanning runs on-device over files you select using signature and structural checks; no file content, hash, or verdict is uploaded.

3. Upstream Encrypted DNS Providers

When a DNS query is allowed by your local filtering rules (or run manually in the web platform’s DNS Lab), it is resolved by your selected upstream DNS provider:

  • Cloudflare (1.1.1.1) — Cloudflare 1.1.1.1 Privacy Commitment
  • Quad9 (9.9.9.9) — Quad9 Privacy Policy
  • AdGuard DNS — AdGuard DNS Privacy Notice
  • Google Public DNS (8.8.8.8) — Google Public DNS Privacy Notice
  • Custom DNS Resolver — Subject to the privacy policy of the operator you configure.

4. Local Activity Logging, Browser, Files & User Deletion Controls

  • Optional Local Logging: Per-domain DNS query logs are stored exclusively on your device and can be toggled off at any time in the Activity tab.
  • Automatic Retention Pruning: Local DNS logs are automatically purged after your selected retention window (1–90 days).
  • One-Tap Deletion: Tapping Clear History in the Activity tab permanently deletes local DNS logs and historical statistics. Security → History provides a separate control for persisted scan reports.
  • Platform Backups: App-private data is excluded from Android cloud backup and device transfer. Manual JSON exports omit DNS query history, scan reports, storage passwords, search history, and download history.
  • Companion Web Platform (/app/): Runs locally in your browser using static files. Configuration snapshots and salted, k-anonymous aggregate counters remain in your browser storage until you clear them; no data is transmitted to a project backend.

4A. Private Search and Built-In Browser

DuckDuckGo is the default search provider; Google can be selected. Search queries go over HTTPS to the selected provider. Search suggestions are off by default. Private mode disables WebView cookies, DOM storage, and cache and clears session data on exit, without claiming network anonymity.

4B. SAF Files, Security Reports, and Duplicates

Files and folders are accessed only after you grant an Android Storage Access Framework URI. AdShield Pro does not request all-files access and cannot read other apps’ private sandboxes. Scans, duplicate checks, and hashes run locally.

4C. Nextcloud / WebDAV and Optional Storage Providers

No cloud storage provider is connected by default. If you configure one, account metadata stays in local Room storage and passwords are encrypted with an Android Keystore AES-GCM key. Transfers go directly between your device and the server you authorized.

4D. Direct-Media Downloads

Inspecting or downloading a permitted direct HTTPS media URL contacts that media host directly and stores download history locally in Room until you delete it. AdShield Pro does not bypass authentication, DRM, or site restrictions.

4E. On-Device AI Agent

The Agent’s task text and findings stay on the phone. The bundled model needs no account, AI API key or provider connection. The app removes any retired Agent connection from its on-device credential store without removing other providers’ settings. This does not delete old provider-side data or revoke previously issued keys.

The Agent’s DNS benchmark sends fixed example.com queries only if approved. Settings diagnostics and benchmarks send the name you enter to the configured or tested DNS providers. When failover is enabled, selected backups may also see a DNS lookup. A custom DoH URL may need a separate system lookup for the endpoint hostname; the requested name does not fall back to plaintext.
